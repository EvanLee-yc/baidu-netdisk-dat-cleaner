# 百度网盘 .dat 视频批量清理器

一个跑在百度网盘网页版上的油猴脚本，用来**批量删除 `.dat` 格式的视频文件**。

主文件：`baidu-netdisk-dat-cleaner.user.js`

---

## 一、它到底在做什么

**它做的事和你手动做的一模一样：搜索 `.dat` → 删掉这一批 → 再搜索 → 再删……**
区别只是它自动循环，不用你一次次点。

为什么要循环？因为网页版搜索一次最多给出 **500 条**（就是那个"搜索结果最多 500 条"的限制），
删完这批，下一批才会露出来。v1.1 的默认模式就是自动跑这个循环，直到搜不到新文件为止。

---

## 二、两种模式

| | 搜索模式（默认） | 遍历模式 |
| --- | --- | --- |
| 做什么 | 用搜索接口找 `.dat`，删一批再搜下一批 | 逐个目录递归扫描，拿全量清单 |
| 成本 | 正比于「命中数 ÷ 500」轮 | **正比于「目录数量」** |
| 清单完整度 | 看不到完整清单（边删边露） | 完整清单，可人工核对 |
| 适合 | 文件多、目录多，只想尽快删干净 | 想先看清全部清单再决定删不删 |

**实测（模拟 3000 个目录、18000 个 `.dat`）**：遍历模式 3005 次请求；搜索模式 577 次请求。
请求数降到约 **1/5**。而遍历模式的成本随**目录数**线性增长、搜索模式只随**命中数**增长，
所以你的网盘越大，差距越明显。

> 一句话建议：**先切「遍历模式」试运行一次**（拿到完整清单核对规则是否符合预期），
> 确认无误后**再用「搜索模式」正式删**。

---

## 三、加载方式（二选一）

**油猴脚本（推荐）**：装 Tampermonkey → 新建脚本 → 把 `.user.js` 整个内容粘进去保存 →
刷新 `https://pan.baidu.com/disk/main`，右下角出现面板。

**控制台临时用**：打开并登录网盘 → F12 → Console → 把文件内容粘进去回车。
也可以直接敲命令：

```js
bdcl.run(true)    // 试运行（只扫描不删）
bdcl.printList()  // 打印清单
bdcl.run(false)   // 真正删除（会弹确认框）
```

---

## 四、使用顺序

1. **改配置**（脚本顶部 `CONFIG`）：
   ```js
   mode: 'search',              // 'search' 快 | 'walk' 完整
   rootDir: '/',                // 遍历模式的起点
   ext: '.dat',                 // 要删的扩展名
   onlyCategoryVideo: true,     // 只删网盘判定为「视频」的
   excludePaths: ['/重要资料'],  // 路径黑名单
   ```
2. **试运行扫描** → 看清单、看体积。
3. **核对**：点「打印清单」，控制台列出完整路径，并自动复制到剪贴板。
4. **开始删除** → 弹确认框报总数和体积 → 确认后开始。
5. **删错了？** 去回收站恢复，默认保留约 10 天。

---

## 五、判重规则（不会误删的关键）

同时满足三条才会被删：

1. 不是目录；
2. 文件名以 `.dat` 结尾（不区分大小写）；
3. `category === 1`，即**网盘自己把它归类为「视频」**。

第 3 条相当于你手动在网盘的「视频」分类里搜索 —— 效果等价，所以非视频的 `.dat`
（比如某些软件的数据文件）不会被碰到。

---

## 六、搜索模式的三个已知限制（重要）

### 1. 看不到完整清单

搜索结果是"删掉一批才露出下一批"，所以试运行只能看到第一轮。**要完整清单请用遍历模式。**

### 2. 搜索索引有延迟

刚删掉的文件可能还会在搜索里出现一两轮。脚本自带处理：等几秒 → 换排序 → 最后判定。
日志里会写「本轮没有新命中，等 N 秒等搜索索引刷新」，这是正常的，不是出错。

### 3. 窗口可能被"删不掉的文件"占满

如果命中的文件里混着一批**永远不会被删**的东西（非视频 `.dat`、已在回收站的文件等），
它们会一直占据搜索结果的前排，把 500 条窗口占满，导致后面的文件永远露不出来。
脚本会检测到这种情况并明确报出来（不会假装删完了），三种应对方式：

1. **把搜索限定在「视频」分类里**（最彻底）：
   ```js
   searchExtraParams: { category: '1' }   // 参数名以你自己浏览器里的实际请求为准
   ```
   怎么确认参数名：F12 → Network → 在网盘的「视频」分类里搜一次 → 点开 `/api/search`
   请求看它带了哪些参数，照抄进 `searchExtraParams`。
   （默认留空也能正常用，因为第 5 节的三重筛选已经保证了只删视频。）
2. **打开自动兜底**：`autoFallbackToWalk: true`，搜不动时自动切遍历模式收尾（会慢）。
3. **直接用遍历模式**跑一遍。

## 七、效率与参数调优

请求数就是耗时的主要来源。几个有用的旋钮：

```js
searchPageSize: 100,      // 搜索单页条数（实测 100 可用；若接口接受 500 可减少请求数）
searchMaxPages: 5,        // 单轮最多翻几页（5 × 100 = 500，与网页版显示上限一致）
postDeleteWaitMs: 3000,   // 一轮删完等多久再搜下一轮（给索引刷新时间，少白跑一轮）
batchDelayMs: 800,        // 删除批次间隔，太小容易触发风控
batchSize: 100,           // 单次删除携带的文件数，超限会自动拆半重试
```

想快速验证效果，可以先把 `maxFilesPerRun` 设成 200 跑一次，看日志里"第 N 轮"的节奏。

## 八、可靠性与错误处理

| 情况 | 处理 |
| --- | --- |
| 单次删除数量超限（errno 3） | 自动拆半重试 |
| `bdstoken` 过期（errno 112） | 自动重新获取并重试 |
| 登录态失效（errno -6） | 立即停止，提示重新登录 |
| 网盘要求身份验证（errno 132） | 立即停止（风控），提示去网页验证一次 |
| 任务队列未清空（errno 111） | 等 5 秒重试 |
| 文件已不存在（errno -9） | 视为已删 |
| 连续多轮一个都没删成功 | 停止，避免空转 |
| 搜索窗口被占满 | 停止并说明原因 + 三条建议 |
| 单次运行量过大 | `maxFilesPerRun` 安全阀（默认 5 万） |
| 递归异常 | `maxDepth` 上限（默认 64 层） |

## 九、v1.1 修掉的问题

- **「开始删除」按钮以前其实是空转**：v1.0 里点它会走试运行分支，什么都不删也不报错
  （只打一行提示），容易让人以为"已经删完了"。现在点它就是真删，但一定弹确认框。
- **兜底模式下重复计数**：搜索阶段已删的文件会被遍历模式再算一次删除成功。
  现在遍历模式只删「本次实际发现的文件」。
- **区分不了「删完了」和「窗口被占满」**：现在用「搜索结果是否还满一整窗」来判别，
  两种情况分别给出准确的结论（以前会把被占满误报成清理完毕）。
- 新增：请求次数与耗时统计，直接显示在面板上，方便判断效率。

## 十、风险提示（请务必读）

1. **删除进的是回收站，不是永久删除**，默认保留约 10 天，这是最重要的兜底。
2. **有触发风控的可能。** 遇到 errno 132 脚本会立即停止。频繁出现就把 `batchDelayMs`
   调到 2000 以上再试。
3. **首次使用一定先试运行**，并确认 `onlyCategoryVideo` 符合你的预期。
4. 脚本全程在你自己的浏览器登录态里跑，不导出、不上传任何凭据。
5. 网盘接口未公开、可能随时变更。失效时用 F12 抓一次真实请求，
   对照 `apiSearch()` / `apiList()` / `deleteBatch()` 里的参数改即可。
